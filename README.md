# Simple WMS

Автономная модульная WMS для адресного склада. Система выполняет основные
складские операции без обязательного подключения ERP, специализированного ТСД
или конкретной модели принтера. Интеграции и отраслевые функции подключаются
поверх общего складского ядра.

> Статус проекта: разработка `0.1 Alpha`. Интерфейс и API уже пригодны для
> проверки сценариев, но установка, роли, отчёты и стратегии хранения ещё не
> доведены до публичного выпуска.

## Что уже работает

- пользовательские типы логистических единиц: палеты, коробки, бочки,
  контейнеры и собственные типы;
- вложенность единиц и количественный состав по товарам, партиям и единицам
  измерения;
- приёмка, формирование, закрытие, блокировка, карантин и освобождение;
- адресное размещение и перемещение;
- иерархия `склад → зона → проход → стеллаж → секция → ярус → позиция`;
- отгрузка с резервированием, экспедицией и контролем погрузки;
- локальная и транспортная межскладская передача;
- инвентаризация склада без обязательной остановки операций;
- автоматически создаваемые задания кладовщику;
- поиск номенклатуры по названию, коду и штрихкоду упаковки с расшифровкой
  доступного, резервного, карантинного, блокированного и транзитного остатка;
- создание номенклатуры, товарных упаковок и упаковочных штрихкодов из рабочего
  интерфейса с проверкой полномочий;
- внутренняя выдача сотруднику, подразделению или рабочему месту в единицах
  измерения либо упаковках с атомарным списанием и сохранением основания;
- выдача без возврата либо под ответственность, частичный возврат по исходному
  документу, карантин и автоматическое списание ответственности по нормативу;
- рабочее место, компактный web-экран ТСД и карточки объектов;
- генератор универсальных демо-единиц: от палет с коробками до еврокубов с
  прямым количественным содержимым;
- PostgreSQL, Alembic, резервное копирование и health check;
- PDF-этикетки и RAW TCP-печать на проверенном профиле АТОЛ ТТ42 / HPRT
  XT100.

Рабочий интерфейс и ТСД используют универсальные `LogisticUnit`, документы и
задания. Историческая модель пилота больше не является пользовательским
интерфейсом продукта.

## Интерфейсы

- `/work` — очередь заданий и пошаговая операция кладовщика;
- `/terminal` — компактный экран для телефона, планшета или ТСД;
- `/stock` — поиск и создание номенклатуры, фактические остатки, упаковочные
  коды и внутренняя выдача;
- `/cards` — поиск логистической единицы или адреса и просмотр истории;
- `/demo` — управляемое формирование демонстрационного склада;
- `/docs` — интерактивная документация REST API;
- `/health` — проверка состояния приложения.

Сканер штрихкодов работает в стандартном режиме клавиатурного ввода.

## Быстрый запуск

Требования: Python 3.11+, PostgreSQL для рабочего контура. SQLite подходит для
локальной разработки и автоматических тестов.

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
alembic upgrade head
python -m app.seed
uvicorn app.main:app --reload
```

После запуска откройте `http://127.0.0.1:8000/work`.

Для PostgreSQL укажите в `.env`:

```dotenv
DATABASE_URL=postgresql+psycopg://wms:change-me@127.0.0.1:5432/wms
```

## Проверка

```bash
pytest -q
alembic current
alembic check
curl http://127.0.0.1:8000/health
```

Автогенерация миграции всегда требует ручной проверки:

```bash
alembic revision --autogenerate -m "описание изменения"
alembic upgrade head
```

## Архитектурные принципы

- складские ограничения проверяются на backend, а не только в интерфейсе;
- web, ТСД, оборудование и интеграции вызывают один набор бизнес-операций;
- физические единицы моделируются универсально, без отдельной логики для
  палеты или коробки;
- изменения состава, статуса и адреса фиксируются в журнале событий;
- интеграции с 1С и другими ERP не проникают в складское ядро;
- заказные функции поставляются модулями, а не отдельными расходящимися
  версиями продукта.

## Модули развития

Приоритетное направление интеграции — 1С. Также запланированы расширенный
контроль качества, FIFO/FEFO, регуляторная прослеживаемость, заказные драйверы
оборудования и отраслевые пакеты. «Честный ЗНАК», ЕГАИС, OCR приёмки и POS с
рабочим местом кассира рассматриваются как отдельные коммерческие модули.

## Замороженный пилот

Предыдущая демонстрационная система сохранена в [`legacy/pilot`](legacy/pilot)
и в Git-теге `pilot-freeze-2026-08-03`. Она нужна только для воспроизведения
показа и сравнения поведения. Новая разработка в этом каталоге не ведётся.

Активное приложение и чистая baseline-миграция содержат только универсальную
модель. Таблицы и API пилотных `Box` и `Pallet` остались только в замороженном снимке.
Базы старого пилота не обновляются новой цепочкой Alembic: для перехода их нужно
сохранить как архив и развернуть чистую базу универсальной системы.
